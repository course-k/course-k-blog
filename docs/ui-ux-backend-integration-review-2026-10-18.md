# 採用UIの引き継ぎ確認と結合検証

2026-10-18。本人から[UI引き継ぎ](https://github.com/course-k/course-k-blog/blob/feat/adopted-blog-ui/docs/ui-ux-review-handoff-2026-10-18.md)を受領。対象はPR #3、実装07038b3／引継ぎを含むcb649c7。画面構成の採用は維持する。mainへのマージや正式公開は実施していない。

## 確認済み

- 対象チェックアウトは未コミット変更なし。型検査、固定APIによる本番SSR 3件、runtime 3件を再実行して成功。ARM64の本番コンテナビルドも型検査を含め成功。既存の画面テスト11件は引き継ぎ元の結果であり、今回の再実行とは区別する。
- 管理UIが使用するsession、admin/postsのGET/POST/PUT、publish/unpublishとversionは、現Go APIが提供している。作業版と公開版の分離、競合409、固定ID・初回公開日の契約を維持する。
- 公開本文とプレビューのMarkdownは共通部品。見出しと目次は同じ解析木から生成し、生HTMLを無効のまま維持している。
- 新UIは独立した検証用イメージとしてビルド。元チャットの古いUIイメージやローカル8080を置換しない。AWS試験での一時配置とGitブランチのマージは区別する。

## 画面側で確認が必要な点

Editor.tsxのchooseはdirtyだけを確認し、uncertainを確認せず選択・新規作成時にfalseへ戻す。公開要求の応答消失などで、保存済みのためdirty=falseかつuncertain=trueになる経路がある。その状態で別記事／新規記事を選ぶと、サイト内遷移で設けた結果不明の確認を経ずに警告が消える。コードの状態遷移を追って確認した指摘であり、実ブラウザでの再現試験は未実施。公開前の画面結合検証で、結果不明時の選択確認を追加するか、明示的に結果を破棄する操作とするか確認する。今回、別担当のUIコードを変更していない。

## API残件

現Goコードは自作記事一覧のみを返す。外部記事の種別・元URL・媒体・同期結果、画像の保存と参照、バックアップ状態、hasNextは未提供。これらは画面構成完了と区別し、API契約・実装・画面接続を順に進める。新規作成の応答消失に対する冪等キーも現APIにはなく、UIが自動再送を止めている状態を維持する。

AWSに新UIと実Go/RDSを一時配置し、HTTPS経由のHTTP確認31項目が成功。本文SSR・目次・静的JS/CSS、認証、下書き／公開／更新／非公開、公開版維持、競合、固定IDと初回公開日を確認した。実ブラウザでの編集操作・ハイドレーションは未検証。詳細は[AWS実行記録](aws-validation-execution-2026-10-18.md)。HTTPの結合確認を、画面の通し操作完了として扱わない。
