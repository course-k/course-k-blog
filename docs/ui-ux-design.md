## 確認済みの現在地

- 一覧・本文はサーバー取得。本文と編集プレビューは共通Markdownコンポーネント。生HTMLを許可しない。
- 一覧型は id/title/publishedAt/updatedAt。媒体・外部遷移先はない。
- 管理では編集中のdirty、published、hasUnpublishedChangesが別にある。保存→公開は2リクエスト。
- save()は保存後に管理一覧の再取得を待つ。この再取得だけ失敗しても一括したエラーとなり、保存の成否を誤解させうる。公開もrefresh()まで含めた成否表示であり、段階別表示が必要。これはコードから確認した経路で、故障注入試験は未実施。
- 共通のbusy表示では保存中と公開中を区別できない。未保存変更の破棄確認はある。
- 本文のコード・表には横スクロール、画像には最大幅指定がある。長文や各端末幅の実動作は今回未検証。
- 保存された初回Playwright記録を再確認し、ページタイトルに加えてブログ一覧の空状態のアクセシビリティ構造取得にも成功していたと判明。続く取得は別ページで、タブIDの記録がなく同一タブかは確定できない。画素画像による視覚確認は未実施。独立したブラウザでの再確認はアクセス許可を得られず停止した。以後回避アクセスを行っていない。既存画面を「見た」とは扱わない。

## 主な利用の流れ

読者：元公開日順の一覧→題名・媒体・遷移先を確認→自作本文または外部記事→一覧へ戻り別の記事を選ぶ。直接本文へ来る読者は題名と日付→本文→一覧。

本人：ログイン→新規/既存記事を選ぶ→Markdown編集・同じ描画規則のプレビュー→下書きを保存→確認後に公開。公開中の編集でも旧公開版を保つ。管理内で同期・画像・バックアップの状態を把握する。

## 主要判断：問題→根拠→比較→理由と欠点→確認方法

### 媒体をまたぐ記事案内

問題：同じ一覧でも、クリック後に別サイトへ移ることを予測できる必要がある。
根拠の種類：本人の確定要件。catnoseのリニューアル記事には分散した発信を時系列でまとめる意図がある（制作者自身の説明）。
比較：媒体別のセクションに分ける案は元公開日順の一つの一覧と合わないため採らない。共通順序の中で「媒体＋ドメイン＋外部記号」を添える。
理由と欠点：題名を主に読みながら遷移先を確認できるという仮説。ドメイン表示で行が増える。外部リンクは比較モックでは新規タブ、アクセシブル名にも明示。製品の同一/別タブ方針は採用時に統一する。
確認：外部リンクを開く前に行き先を説明できるか、長い題名で媒体が埋もれないか。

### 文字組み

問題：日本語長文、英数字、コードを同じ記事で読む。
根拠の種類：デジタル庁の一般推奨は本文16px以上・行高1.5以上を目安とし、用途による変更を認めている。個人ブログの最適値という規格ではない。
比較：システムゴシック17px/1.85対明朝18px/1.95。コードは等幅。Webフォントを追加しない。
理由と欠点：初期表示の追加フォント取得を避け、環境の日本語書体を使う。環境による字形・改行差がある。明朝が本人に好まれるかは未確認。17/18pxや幅は今回の未検証仮説。
確認：両案で同じ長文を読み、見出しを探す、コードを横に送る、表を読む。実装時はPC/スマホ、200%拡大、代替フォント、公開とプレビューの一致を検証する。

### 配色とリンク

問題：文章・補足・リンクの階層を識別する。
根拠の種類：WCAG 2.2 SC 1.4.3の通常文字4.5:1、大きな文字3:1。Understanding文書は規格の解説。リンクの下線は色以外でも識別できる手段。
比較：この段階では両案を同じ中立色にし、配置比較と色の好みを混ぜない。本文#23272b、補足#555e66、リンク#235791、背景#ffffff。暗色では#eeeeeb/#b7bec6/#96c5ff、背景#191b1e。
理由と欠点：媒体ごとの色分けを必須にせずテキストで識別する。ブランドの個性はまだ弱い。色は本人未採用。全状態のコントラスト検証完了ではない。
確認：主要色の計算と実表示、リンク/フォーカス/エラー状態を採用後に確認。

### 保存・公開の操作（管理は設計準備のみ）

問題：保存と公開の取り違え、途中失敗、作業消失を避ける。
根拠の種類：確定した公開状態の意味、既存コード、デジタル庁の操作の役割に応じた階層化という一般推奨。
比較：保存を主ボタン・公開を副ボタンにする案と、公開を主にする案。継続執筆を優先するため前者を推奨。公開を見落とさないよう公開状態と同じ領域に置く。
理由と欠点：頻繁な保存を近くに置く。非公開操作は公開/保存と離し、対象を明記する確認を残す。スマホの固定バーはキーボードとの干渉を検証してから判断する。ボタンの位置と大きさはまだ実装していない。
確認：保存中/保存失敗/保存済み未公開/公開失敗/応答不明を区別できるか。44pxの操作領域は今回採る設計目標であり、WCAG AAの一律必須値と説明しない。
