# 採用UIの実装と検証（2026年10月18日）

状態：フロント実装済み。オフラインの実ブラウザによる部品検証と本番SSRの検証済み。実API・DBを通した今回の結合検証、外部記事・画像アップロード・同期・バックアップの連携は未完了。ブログ全体の完成・公開を意味しない。

## 実装

- 一覧：1列、概要なし、白地、20pxの輪郭付きカード、媒体と日付を上段に配置。小さな7pxの媒体印。カード全体をリンクとし、キーボードのフォーカスを輪郭に表示。
- 本文：B案の明朝系18px・行高2.1（狭幅17px）。コードは等幅。本文とプレビューは共通Markdown。生HTMLは無効のまま。
- 目次：Markdown解析後の同じ木から見出しとアンカーを生成。重複見出しでもIDは一意、コードブロック内を誤検出しない。PCは右側、900px以下は本文上部の折りたたみ。見出しがなければ表示しない。
- 管理：PCは編集・プレビュー並列、600px以下は編集／プレビュー切替。未保存、保存済みの未公開変更、公開状態を区別。
- 保存成功後の一覧再取得失敗と公開失敗を区別。通信で結果が不明なときは入力を保持し再送を止め、再取得で確認する。新規記事でIDが不明なときは題名の一致だけで自動的に別記事へ紐付けない。
- サイト内遷移にも未保存・結果不明の確認を追加。保存処理中の遷移を止める。タブを閉じる場合のbeforeunload確認も維持。
- サイト名「course_kのブログ」、暫定紹介文を反映。白＋チャコールにライムの小さなアクセント。ライムは本文文字色にしない。
- 外部記事用カードは媒体名と新しいタブの予告、target/relを実装。HTTP(S)以外はリンクにしない。既存APIは自作記事のみなので、本番一覧に架空の外部記事を挿入していない。外部用表示型はフロント部品用で、API契約の確定ではない。

## 検証方法と境界

実装したReact部品を専用HTMLへ束ね、Chromeの別プロファイルで描画。about:blankへHTMLを設定し、ブラウザコンテキストをofflineにして全ネットワークを遮断。図だけは予約ドメインui-fixture.invalidへの要求をテスト内の固定SVGで応答。APIはメモリ内の架空データ。実サーバー、既存ブラウザ、localhost:8080、既存DBにはアクセスしていない。

`frontend/ui-tests/verify.mjs` は画面幅1280／390／320、目次の開閉・アンカー、同名見出し、コード除外、画像、横はみ出し、1列、外部リンク属性、管理の並列／切替、未保存離脱、保存成功／公開失敗／一覧失敗／応答消失／競合を検証する。外部タブへの実ネットワーク遷移は未実行。

`frontend/ui-tests/ssr.test.mjs` は本番ビルドのentry.fetchへプロセス内でRequestを渡す。API取得だけを固定応答へ置換し、HTTPサーバーは起動しない。本文・目次・一覧がHTMLに含まれること、404、取得失敗を空一覧にしないことを確認。実Go API・PostgreSQL・Cookieの結合検証ではない。

実行結果：本番ビルド、型検査、SSR 3件、既存runtime 3件成功。画面テストの結果は[記録](ui-ux-evidence/implementation/results.json)を参照。

文字コントラスト（白地）：本文13.86:1、補足5.55:1、リンク7.70:1、エラー7.21:1。入力枠3.24:1。ライムの印は媒体名を併記する補助装飾で、色だけを識別手段にしない。全アクセシビリティ要件の完了宣言ではない。

## 検証時に直したこと

- 作業場所のnode_modulesを別チェックアウトへシンボリックリンクした状態ではReactの重複解決でSSRが500になった。依存を作業場所内へコピーし直して解消。最終SSR 3件は成功。ライブラリのバージョン変更なし。
- インライン検証用スクリプトがroot要素より先に動く問題を、検証用HTMLのbody末尾配置で解消。
- 未保存離脱のキャンセル時、ナビゲーションPromiseを待つ検証コードが停止したため、ダイアログ発生と入力保持を直接確認する方式へ修正。
- 表の細い列と先頭見出しの余白をスクリーンショットで確認して調整。
