# UI/UX比較案：採用基準と実装前の状態整理

最新の実装・検証範囲は[採用UI実装記録](ui-ux-implementation-2026-10-18.md)を参照。初期の未実装・未検証記述と区別する。

2026-10-18更新。最新の採用結果は[最新の採用事項](ui-ux-decisions-current.md)を参照。一覧・本文・目次・外部別タブ・管理配置は採用済み。以下の初期2案の推奨と判断待ちは比較履歴。表示切替の通知だけを採用と扱わない。

## 同じ内容で比べる

両案には同じ6件の取得済み外部記事と比較用自作記事を表示。実記事の長い題名、媒体、元公開日を確認する。本文は同じ架空の長文・コード・表を用いる。本人の実績としては扱わない。

| 観点 | 記事を見渡す | 一編ずつ読む | 採用の判断基準 |
|---|---|---|---|
| 記事選び | 日付列を揃え題名と媒体を一覧する | 大きな題名を広い間隔で読む | フォーム関連の記事を選ぶ課題で、題名や媒体の読み戻しが少ない方。時間の閾値は捏造しない |
| 外部への遷移 | 題名下の媒体・ドメイン | 同じ情報を記事単位で表示 | クリック前に外部か自作かを説明できる。色や矢印だけに頼らないことは両案共通 |
| 長文 | ゴシック17px/1.85 | 明朝18px/1.95 | 同じ3段落を読み、読み返しや疲れについて本人が判断。書体の好みと機能検査を分ける |
| 節の参照 | PC側方目次 | 冒頭目次 | コードから説明へ戻る際の移動が少なく、本文幅も確保できる方。短文では目次自体を省く候補 |
| スマホ | 日付・題名・媒体を縦にする | 題名中心の縦構成を継続 | 題名を省略せず操作領域が重ならない。本文以外の横はみ出しなし |
| 管理への展開 | 広い画面では編集/プレビュー並列 | 本文幅に寄せた編集/プレビュー切替 | 入力と見え方を頻繁に照合するなら並列、文章を続けて書くなら切替。いずれもスマホは切替を候補とする |

推奨は「記事を見渡す」。技術記事を選ぶ・本文を参照する用途を重視した仮説で、利用実験の結果ではない。一覧A＋本文Bも選択可能。本人の読む好みに反すれば推奨を変更する。

## 両案とも満たす条件（好みで省略しない）

- 元公開日順と固定URL/初回公開日を維持。外部本文は転載しない。
- タイトル全文の折返し、媒体名、遷移先を表示。自作記事に外部記号を付けない。既存index.tsxでは自作記事にも↗があるため、混在導入時の修正候補。
- 一覧は取得失敗と0件を区別。本文の404と通信失敗を区別する。
- 本文とプレビューを同じMarkdown描画規則にする。
- キーボードで全操作に到達しフォーカスを判別できる。200%拡大でも操作が失われない。
- 通常文字のコントラスト4.5:1以上を基準とする。配色の主要6組の計算は済み、最小6.61:1。実画面の全状態は未検証。

## 管理画面の状態・文言案

保存状態と公開状態を別の情報として同時表示する。以下は表示仕様案で、APIや状態の意味を変更するものではない。

| 状態 | 表示案 | 次の操作と保持するもの |
|---|---|---|
| 未保存 | 保存していない変更があります | 下書きを保存。切替/離脱時は破棄確認 |
| 保存処理中 | 下書きを保存しています… | 二重送信を抑止。入力内容を消さない |
| 保存済み・公開中・変更あり | 下書きは保存済み／読者には以前の公開版を表示中 | 更新を公開する |
| 保存失敗が確定 | 下書きを保存できませんでした | 入力保持、再試行。入力不正なら対象を案内 |
| 保存成功・公開失敗が確定 | 下書きは保存済み／公開できませんでした | 以前の公開版維持を案内。初回なら未公開と表示 |
| 保存/公開の応答不明 | 処理結果を確認できませんでした | 状態再取得して照合。未確認で成功/失敗と断定しない |
| 公開成功・一覧取得失敗 | 公開しました／管理一覧を更新できませんでした | 一覧の再取得。公開の再送を求めない |
| 競合409 | 別の更新があるため保存できませんでした | 入力を保持し最新内容との比較。無断上書きしない |
| 認証切れ401 | ログインし直してください | 入力を保持して復帰。保存成功扱いにしない |
| 同期失敗 | 対象媒体、最終成功日時、今回の失敗 | 既存記事保持。取得範囲不足と0件成功を区別 |

既存save()は保存後の管理一覧取得まで待つ。その取得失敗で公開処理が始まらない経路があるため、操作段階と失敗箇所を分ける。実際の故障注入検証はまだしていない。

## ブラウザが必要な残作業

1. 両比較案をPC（1280px程度）・スマホ（390px、320px）で実描画。現モックの「スマホ幅」は幅を狭める比較操作にすぎず実端末検証ではない。
2. 長題名、長文、コード、表、画像と代替テキスト。画像は現比較モックに未収録。採用前に画像を含むケースを追加する。
3. リンク、目次、戻る操作、フォーカス移動、キーボード操作、拡大、暗色表示、代替フォント。
4. 管理の視覚モックを2案作成（並列編集／切替編集）。未保存・保存中・失敗・部分成功・結果不明を切替可能。実際の保存・公開はせず、簡易表示は共通Markdown描画の代替実装ではない。実描画・操作は未検証。
5. 採用後の実装でAPIに接続し、保存/公開/非公開、固定URL、SSR、認証切れ、409、通信断、部分成功を検証する。未接続の外部同期・画像・バックアップは契約成立後に検証。

## 完了と未完了の境界

完了：2案の比較用画面ソース、実記事メタデータの照合、設計理由、採用基準、管理状態表、API相談事項。
未検証：比較画面の実描画/操作とすべての実アプリ統合。
採用済み：一覧と本文の方向性（最新採用事項を参照）。現時点で権限問題のために本人だけが必須で行う操作は特定できていない。

## 管理比較の追加

並列案は入力と表示の照合を優先し、切替案は入力幅と集中を優先。保存・公開の位置と状態文言を共通にし、操作の意味を案ごとに変えない。管理モックのJavaScript構文を検査。ブラウザ実行、実APIとの接続は未検証。画像入り本文の比較追加は残作業。

## 採用記録：管理画面の並列編集（2026-10-18）

本人が管理比較に対して「並べる方がいいです」と選択。「編集と見え方を並べる」案を採用。比較対象は「書くことに集中する」（編集/表示切替）案。

本人の選好として確認できたのは並列配置であり、その理由までは発言されていない。設計上の狙いはMarkdown入力と表示を同時に照合できること。欠点は各領域の横幅が減ること。狭い画面で編集/プレビュー切替へ移行する方針は実装側の提案で、切替幅は実描画で検証して決める。

採用範囲は管理画面の編集・プレビュー配置。一覧・本文のデザイン、配色、全操作文言の一括承認ではない。実API接続・共通Markdownへの統合・実描画検証は未完了。比較用簡易表示を本番レンダラーへ持ち込まない。

## 採用後の評価基準

- 比較は名前付きの縦並び、同じ記事・同じ表示幅とする。カルーセルは本人が比較しづらいと指摘したため既定にしない。
- 配色比較では形・文字・余白を固定し、変更範囲を守る。
- 一覧は1列・概要なし・背景の塗り分けなし。媒体名を必ず残し、ライムとQiitaの緑の識別を色差だけに依存させない。
- 本文Bの明朝体を実記事で確認する。旧主要6組のコントラスト計算を新しいライム配色の検証として転用しない。
- スマホ目次は折りたたみ。外部リンクは別タブとし、操作前に媒体・新規タブが分かることを確認する。
- 模式図は追加済みだが、実画像・代替テキスト・読み込み失敗の検証は残る。
- 管理モックは並列を採用済み。実API、保存と公開の段階的失敗、キーボード、SSR、型検査・本番ビルドは未検証。
