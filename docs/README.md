# ドキュメントの入口

現行の仕様と選択理由、開発・運用に必要な情報を管理する。

| 知りたいこと | 読む文書 |
|---|---|
| 何を作るか、何を選び、なぜ選んだか | [現行設計](current-design.md) |
| 画面の構成・配色・文字組みと、その理由 | [UI設計](ui-ux-decisions-current.md) |
| 今どこまでできていて、何が残るか | [公開までの進捗台帳](blog-publication-roadmap-2026-10-18.md) |
| コードと文書をどう分け、何をGitへ保存するか | [リポジトリ構成と保存方針](repository-organization.md) |
| AWS設定・検証配置・撤去の手順 | [AWS手順](../infra/README.md) |
| ローカル起動・検証の方法 | [リポジトリREADME](../README.md) |

文書を読むために会話や旧計画を追う必要がない状態を維持する。主要判断は比較案・採用理由・欠点・制約を現行設計へまとめ、UIの判断はUI設計へまとめる。進捗は公開台帳だけを更新し、別の台帳を増やさない。

作業経緯・引き継ぎ指示・一時的な出力を保存する目的のhistory / evidenceディレクトリは設けない。検証は条件・結論・限界を要約し、再実行する試験コードは実装の近くに置く。LLMの利用範囲は現行設計とPRに明記する。
