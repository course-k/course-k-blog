# UI/UXの採用仕様と理由

最終更新：2026-10-19。採用した画面仕様、比較案、理由、欠点と制約をまとめる。本人の好みと一般的な知見・実証結果を区別する。実装・受入の進捗は公開台帳で管理する。

## 設計判断のつながり

### 記事選び
問題：複数媒体の本人記事を、元公開日順に一緒に眺めて選ぶ。
知見：カードの共通領域による情報のまとまり（一般推奨）と本人の1列・広い余白の好み。
比較：日付列の一覧、余白中心の一覧、輪郭付きカード、輪郭付きの3方向。
採用理由：本人が輪郭付き・柔らかな案を好むと確認。タイトル、媒体、日付を一単位として見せる狙い。
欠点：概要なしではタイトルに選択材料を依存する。カードの余白で表示件数が減る。
確認：長いタイトル、媒体識別、狭幅、キーボード、外部遷移の予測可能性。見つけやすさが実証済みとはしない。

### 読書
問題：日本語長文と技術的なコード・表を読めること。
比較：ゴシックの自然な案、明朝の随筆案、コンパクトで見出し線を付ける案。
採用理由：ゴシック・明朝・コンパクトな表示から、本人が明朝の読み味を選好。18px・行高2.1は設計の出発点で、固定の最適値ではない。
欠点：縦に長くなること、OSのフォント差、コードとの書体差。
確認：実記事・コード・表・写真・代替テキスト・200%拡大、本文とプレビューの一致。現サンプルの模式図は実画像検証の代替ではない。

### 配色
問題：本人らしさを出しつつ、文章・操作・掲載先の識別を妨げない。
比較：大きな媒体別の装飾と、小さな色印・文字ラベルによる識別。
採用理由：本人のNinjaへの愛着。サイト全体のテーマと媒体識別色を別の役割として扱う。
欠点：ライムとQiitaの緑が近い。小さな印は色差だけでは識別しづらい。
確認：媒体名を必ず併記し、ライムを本文文字色へ安易に使わない。明暗テーマ、リンク、フォーカス、失敗状態のコントラストを個別検証。新配色は未検証。

## 実装の責務と操作結果

- 配色・媒体名・別タブ指定は表示側で管理し、表示上の選択だけを理由にAPIやDBの列を増やさない。
- 本文とプレビューは同じMarkdown部品を使う。目次は同じ解析木から見出しIDとともに生成し、専用APIを追加しない。生HTMLは許可しない。
- 混在一覧は自作／外部の種別・元URL・媒体・元公開日を明示的に受け取る。URLの見た目から種別を推測せず、概要は必須にしない。混在一覧APIはarticles/hasNextを返す。
- 保存失敗、保存成功後の一覧再取得失敗、保存成功・公開失敗、応答消失による結果不明を区別する。入力を保持し、結果不明を操作失敗と断定して自動再送しない。
- 結果不明のまま切替・新規・離脱・ログアウトするときは破棄確認を出し、取消なら警告と入力を保持する。記事を選び直す場合は最新状態を取得し、古い一覧情報で公開状態を決めない。自作記事は作成キー/固定ID、外部補正は媒体と元IDで保存結果を確認し、入力を書き換えず、確認失敗や再ログインでも未確認状態を維持する。
- 同期・画像・バックアップは既存の管理画面へ接続する。失敗を0件や成功へ置き換えず、取得範囲不足・再試行可否を案内する。画像は5MiB/1200万画素以内のPNG/JPEGに制限し、挿入後の文章と共通プレビューで確認する。

### 追加機能の配置と復帰

外部記事の補正とバックアップ状態は、執筆領域の後に見出しと境界線で区切る。専用画面や常設サイドバーへ広げる案に対し、本人一人・低頻度の管理なので移動を増やさない。取得範囲・失敗・最終成功は見せ、復元用IDなど普段使わない情報はdetails内に置く。管理画面が縦に長くなる欠点を受け入れ、配色や装飾を増やさない。追加部分の最終的な好みは本人による確認が残る。

公開用ログインは別ウィンドウで行い、元の本文・外部補正・結果不明をメモリに保持する。失効時には編集部品を隠して操作を止め、再ログイン後に同じ入力へ戻す。明示したログアウトでは破棄確認後に部品ごと破棄する。ブラウザ保存領域への下書き自動複製は追加しないため、再読み込み・タブ終了・端末故障まで入力を保証するものではない。

画像選択は本文内のカーソル位置へのMarkdown挿入とし、専用の画像管理画面を作らない。選択時の検証・アップロード中は編集操作を止め、完了後はプレビューで確かめる。ファイル名由来の代替テキストは本人が本文内で修正する。公開中の画像と未公開の差し替え画像は画面では同じ形式だが、閲覧権限はGoで公開参照から判定する。
