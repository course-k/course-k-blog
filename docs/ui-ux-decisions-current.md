# UI/UXの採用仕様と理由

最終更新：2026-10-31。採用した画面仕様、比較案、理由、欠点と制約をまとめる。本人の好みと一般的な知見・実証結果を区別する。実装・受入の進捗は公開台帳で管理する。

## トップページのプロフィールと月別

人物のプロフィール画像は本人提供のバイク写真。比較案Bを採用し、837px角の元画像で左130px・上20pxから550px角に相当する範囲を円内に表示する。写真全体の内容を変えず、人物とバイク上側に寄せ、車輪や車体下部を枠外にする。配信用はメタデータを持たないWebP約113KBとし、デスクトップ88px・狭幅56pxでも同じ構図を維持する。

本人が「上にプロフィール」案を選択した。写真の右側に題字とGitHub・Qiita・noteへのリンクを並べ、紹介文は置かない。写真との間隔はPCで24px・狭幅で16px。詳細なプロフィールページは本人の今後の構想で、まだ作成せず、リンクも置かない。経歴は創作しない。プロフィールと記事は共通の幅で揃え、PC・スマホとも1カラムで表示する。左右の常設プロフィール・3カラムとも比較し、記事の幅と余白を保つ構成を優先した。

「月別に探す」は記事一覧直前に置き、年・月・件数を必要時に展開する。選択中の月を記事一覧の見出しにも表示し、「すべての記事に戻る」を常設する。新着記事を読む流れを優先しながら、本人が好む年月からの探索を残す判断。[段階的開示](https://www.nngroup.com/articles/progressive-disclosure/)はこの構成の参考であり、月別の利用頻度や上配置の優位性をこのブログで実証したものではない。[右サイドバーの調査](https://www.nngroup.com/articles/fight-right-rail-blindness/)も右配置を禁止する根拠とは扱わない。

## 設計判断のつながり

### 記事選び
問題：複数媒体の本人記事を、元公開日順に一緒に眺めて選ぶ。
知見：カードの共通領域による情報のまとまり（一般推奨）と本人の1列・広い余白の好み。
比較：日付列の一覧、余白中心の一覧、輪郭付きカード、輪郭付きの3方向。
採用理由：本人が輪郭付き・柔らかな案を好むと確認。タイトル、媒体、日付を一単位として見せる狙い。
欠点：概要なしではタイトルに選択材料を依存する。カードの余白で表示件数が減る。
確認：長いタイトル、媒体識別、狭幅、キーボード、外部遷移の予測可能性。見つけやすさが実証済みとはしない。

### 読書
問題：日本語長文と技術的なコード・表を読めること。
比較：ゴシックの自然な案、明朝の随筆案、コンパクトで見出し線を付ける案。
採用理由：ゴシック・明朝・コンパクトな表示から、本人が明朝の読み味を選好。18px・行高2.1は設計の出発点で、固定の最適値ではない。
欠点：縦に長くなること、OSのフォント差、コードとの書体差。
確認：実記事・コード・表・写真・代替テキスト・200%拡大、本文とプレビューの一致。現サンプルの模式図は実画像検証の代替ではない。

### 配色
問題：本人らしさを出しつつ、文章・操作・掲載先の識別を妨げない。
比較：大きな媒体別の装飾と、小さな色印・文字ラベルによる識別。
採用理由：本人のNinjaへの愛着。サイト全体のテーマと媒体識別色を別の役割として扱う。
欠点：ライムとQiitaの緑が近い。小さな印は色差だけでは識別しづらい。
確認：媒体名を必ず併記し、ライムを本文文字色へ安易に使わない。本番画面は本人が確認し受入済み。ただし、全状態のコントラスト測定や環境別のアクセシビリティ評価を完了した意味ではない。

## 実装の責務と操作結果

- 配色・媒体名・別タブ指定は表示側で管理し、表示上の選択だけを理由にAPIやDBの列を増やさない。
- 本文とプレビューは同じMarkdown部品を使う。目次は同じ解析木から見出しIDとともに生成し、専用APIを追加しない。生HTMLは許可しない。
- 混在一覧は自作／外部の種別・元URL・媒体・元公開日を明示的に受け取る。URLの見た目から種別を推測せず、概要は必須にしない。混在一覧APIはarticles/hasNext/monthsを返す。monthsは全公開記事の日本時間の年月・件数で、表示中のページだけを集計しない。
- 保存状態は固定の表示領域に「未保存」「保存中…」「保存済み」「保存できませんでした。再試行します。」「保存結果を確認しています…」「再ログインが必要です。入力は保持しています。」「保存先が別の画面で更新されています。」を出し、入力のたびに通知を出さない。「保存済み」はサーバーの応答で確認した場合だけ表示し、送信中・失敗した画像があれば全体を保存済みにしない。
- 結果不明は失敗と断定せず、読み取りで照合する。保存中も入力でき、古い応答で新しい入力を戻さない。画面の移動では確認ダイアログを出さずに保存してから移り、保存できない時だけ「編集を続ける」「再試行」「変更を破棄して移動」を示す。
- 再読み込みや通信断に備え、端末内（IndexedDB）にも一時保存する。認証後に「前回の編集内容を復元しますか？」と尋ね、勝手に新規画面へ流し込まない。
- 記事一覧は自作記事のタイトル・状態・更新日時だけを示し、空のタイトルは表示時だけ「無題」とする。検索・絞り込み・常設サイド一覧は置かない。
- 同期は202の受付を成功と表示せず、待機・実行中は対象アイコンに進行を示す。部分取得は「取得可能な範囲を同期しました」とし、10分の制限は残り時間を示す。バックアップは設定画面の表示中だけ15秒ごとに状態を更新する。

### 追加機能の配置と復帰

公開用ログインは別ウィンドウで行い、編集中の入力はメモリと端末内に保持する。失効時には編集部品を隠して送信を止め、再ログイン後に同じ入力から保存を再開する。ログアウトは設定画面だけに置き、成功時に端末内の復旧用コピーを削除する。

- 本人の好み：上表の選択。読みやすさの一般的な実証とは区別する。

- [Zennのデザイン調整](https://zenn.dev/team_zenn/articles/ba9245ff5b92f3)：文字・色・余白・影の相互関係、意味のある装飾。著者は後任デザイナーFUJISAWA 9000であり、catnose本人の発言と混同しない。
- [カード](https://www.nngroup.com/articles/cards-component/)、[共通領域](https://www.nngroup.com/articles/common-region/)：まとまりの利点と密度・走査の欠点を参照。カードが常に速く探せるという主張ではない。
