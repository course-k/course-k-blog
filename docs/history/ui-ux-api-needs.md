## API変更なしで進められること

既存published/hasUnpublishedChangesと画面のdirtyを分離表示。保存、一覧再取得、公開の処理段階を分ける。一覧再取得失敗を保存失敗とまとめない。Markdownの共通描画を維持し、文字組み・折返し・フォーカス・空状態・状態別文言を改良する。

## 結果が不明な通信失敗

応答が失われた際、操作自体の失敗とは断定できない。既存記事はIDで最新状態を再取得し、入力内容は保持して比較する。新規作成の応答不明はIDが手元にないため再送による重複に注意。冪等キー等の契約が必要か元担当と相談する。UI担当だけで導入方式を決めない。

公開成功後の再取得失敗では公開成功を保持して一覧表示の失敗を別案内。保存成功/公開失敗は作業版保存済み・旧公開版維持を表示。再公開・更新でIDと初回公開日を変更しない。

## 採用方針による更新（2026-10-18）

- 一覧は概要なしを採用。概要/excerptを必須API項目として追加要求しない。題名・元公開日・媒体・遷移先は引き続き必要。
- 外部記事は元のURLを別タブで開き、紹介ページを挟まない。外部本文を取得・転載する要求ではない。URLが外部か内部かは明示的な種別で判別し、文字列の見た目から推測しない。
- 媒体色、独自テーマ、サイト名、紹介文、リンクのtargetは表示側の設定として扱い、今回の選択だけを理由にGo/DBへ色や別タブ設定を追加しない。
- 右側目次とスマホ折りたたみは共通Markdownの見出しから生成する方針。見出しIDの一致は表示側で整理し、目次専用APIを既定で要求しない。
- 本文Bと管理プレビューを同じ描画規則へ統合する。モックの簡易HTMLでAPIの状態を代替しない。
- 既存APIに関する上表は初回コード確認時の情報。元担当が並行実装している可能性があるため、統合前に再確認し、未実装という記述を現在の確定事実として転用しない。
