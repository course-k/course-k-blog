# AWS配備前準備の実装・検証記録

更新：[2026年10月18日のDocker再ビルド・実画面・DB/TLS・負荷の結果](aws-validation-ready-2026-10-18.md)。以下のDocker再ビルド未確認は解消。実AWS未検証は継続。

2026年10月17日。設計PRを基点としたfeat/aws-readinessの変更。AWS課金・DNS変更・既存DBデータの移動なし。UI/外部記事/画像/ダンプ等の新機能は追加しない。

## 変更と意図

- Goに`api healthcheck`コマンドを追加。資格情報やDB接続を初期化せず、loopbackの/api/healthzを3秒以内で確認する。リダイレクトや非200を正常にしない。DB疎通は/api/readyzとして別監視。DB停止で再起動を繰り返す設計を避ける。
- Node用に`server.mjs`と`runtime.mjs`を追加。公式が案内するRsbuildのfetchエントリーと静的配信を、既存依存のsrvxで接続。/healthzはGo/DBに触れず応答。静的ファイル・SSR・404・例外に、以前Caddyにあったnosniff/Referrer-Policy/X-Frame-Options/no-storeを適用。特定の表示ルートだけに適用するミドルウェアより外側で処理する。Cookie・ステータスとストリーム本文を保持する。API転送は実装しない。
- Node起動は`node server.mjs`へ変更。既存srvx依存を使い、新しい依存ライブラリは追加していない。proxyヘッダーを無条件に信頼しない。AWS上の外部URL/Hostの確認は残る。
- AWS公式のRDS公開CAバンドルをGoイメージへ同梱。PGSSLROOTCERTを指定し、verify-full DSNで利用する。秘密鍵ではない。出典・取得日・SHA-256をcerts/README.mdに記録。実RDSでのTLS試験をしたとは扱わない。
- 新規検証DB用のbootstrap.psqlを追加。管理者が専用スキーマと移行/アプリの2ロールを作り、通常アプリはDMLのみ、移行ユーザーはDDLを担当。環境変数から異なる24文字以上のパスワードを受け取り、ソース・コマンド引数へ実値を記入しない。既存本番DBへ実行するスクリプトではなく、再実行時に既存ロールを上書きしない。
- CloudFormationに両コンテナのHealthCheck、独立した移行タスク定義・秘密値取得用ロール、疎通Lambda・EventBridge・SNS・アラームを追加。現在66リソース。移行タスクを常駐サービスへ接続せず、明示的な単発実行にする。
- 疎通LambdaはVPC外から生成APIの/healthz・/api/readyz・/を15分ごとに確認。リダイレクトを追わず、DB準備状態とHTML応答を確認。レスポンス本文/資格情報をログへ出さない。実行失敗と未実行を別アラームで確認。SNSトピックに通知する設定までで、メール等の購読先は未設定。誰にも送信していない。

## 実際に確認したこと

- Go全パッケージのrace付きテスト（count=1）・go vet成功。DB環境変数がないテスト実行の結合試験SKIPと、次項の実DB実行を区別する。
- 既存ローカルPostgreSQLへの結合試験成功（テスト用記事を使う既存の専用試験）。既存の実記事公開・削除・スキーマ変更なし。
- Linux ARM64用Goバイナリのクロスビルド成功。フロント本番ビルド・型検査成功。
- Nodeランタイムの3テスト成功：DB等に触れない生存確認、SSR/静的/404/例外への保護、複数Cookieとリダイレクト保持。
- 更新したNodeサーバーを別ポート13000で一時起動。healthz・一覧HTML・実ビルドのJS・不存在記事404と保護ヘッダーをHTTPで確認。SSRデータ取得は既存ローカルGoを利用。終了後停止し、既存localhost:8080のサービスを変更していない。
- ネットワークなし・ポート公開なしの一時PostgreSQLコンテナでbootstrapを検証。弱いパスワード拒否、移行ロールで初期DDL、アプリロールでINSERT/SELECT成功・CREATE TABLE拒否を確認し、一時コンテナは削除。
- RDS公開CAバンドルをTLSの証明書ストアへ読み込めることを確認。これは接続先ホスト名/署名の負のTLS試験の代用ではない。
- 疎通コードの2テスト成功（対象3経路、ok=false/形式異常の拒否）。AWS上のLambdaや通知実送信は未実施。
- CloudFormationのcfn-lint（東京）成功。参照・構文チェックであり、CloudFormation更新・実環境試験の成功ではない。

## 制約と残件

Dockerのホスト側作業先制限は一時buildxディレクトリで解消したが、その後ベースイメージのレジストリ応答待ちが続いたためビルドを中断した。新しいDockerイメージ全体の作成成功は報告しない。Dockerfile変更・コンテナコマンドは再ビルド後に確認する。

実RDS接続と誤CA/ホスト名の拒否、実AWSのHost/Origin/Set-Cookie・静的配信・更新と障害・Cloud Map切替、VPC Link対策と通知、制限枠内の負荷/容量は未検証。公開用認証強化、バックアップ/復元は別の未完了項目。公開可能な完成版とはしない。

通知先は本人が選び、承認した範囲で接続する。現在のSNSは購読者なしで、アラーム状態は変化しても本人には届かない。稼働開始前に購読・確認を必要とする。疎通に使う生成APIエンドポイントはAWSから到達可能になるため、課金環境の作成時に公開範囲も明示する。

配備の次段階は、Dockerビルド再確認と、作成対象・費用・公開範囲をまとめた実環境検証の確認。AWS認証情報の読み取り・リソース作成は今回行っていない。
