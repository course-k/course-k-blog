# ブログ公開までの進捗台帳

更新：2026-10-18。**進捗・残作業・次の到達点を管理する唯一の台帳。** ファイル名の日付は作成日であり、以後も同じファイルを更新する。仕様は[現行設計](current-design.md)、資料の配置は[構成・棚卸し](repository-organization.md)を参照する。

## 目標と現在地

独自ドメインで、自作記事と外部媒体の本人記事を案内し、本人が継続して執筆・公開・管理できるブログを公開する。学習と技術ディスカッションのため、最終的な設計と選定理由、検証範囲とLLM利用を説明できる状態にする。

**現在は、自作記事の基本機能・採用画面が実装され、新UI＋Go＋実DBのAWS一時配備も確認済み。本番公開・全機能の運用準備は未完了。検証用AWS環境は撤去済みで、本番環境は未作成。**

コメント、いいね、会員登録、検索、SNS投稿連携、将来の別アプリは初回公開の必須へ追加しない。画面構成の採用は完了しており、外部記事・画像等の画面接続まで完了した意味ではない。

## 追加実装前の整理計画

ゴールは、現行設計と採用理由が文書だけで理解でき、必要なコード・設定・検証手順を追えること。新機能・技術の再選定・AWS再配備は含めない。

| ID | 状態 | 作業 | 完了条件 |
|---|---|---|---|
| S1 | 完了 | 最終的な仕様・比較・採用理由・制約を現行文書へ集約し、不要な旧資料・データを削除 | 旧資料をたどらず設計を説明できる。残件を失わず、リンクが有効で、アプリ・設定に変更がない |
| S2 | 完了（オフライン検証） | infraの用途・採用版・AWS反映版を照合。configの再利用処理を秘密値から分離 | 追跡可能な設定と実行入口が揃い、準備・確認・適用・撤去の境界を説明できる。オフライン検証を実施 |
| S3 | 未着手 | 画面・API・DBの依存と責務を確認し、必要な箇所のみ分割 | 分割理由を説明でき、保存・公開・認証の既存動作を対応試験で維持する。行数だけで分割しない |
| S4 | 未着手 | テストの目的・前提・実行順とPRの確認範囲を整える | 別の作業環境で設定と検証を追える。固定API／実API／実DBを区別し、未実行を成功と扱わない |

各段階を検証してから次へ進む。要件の重要な未決事項、費用・DNS・権限変更・不可逆操作は対象と影響を具体化して確認する。既存の権限テンプレートの未コミット変更は別に保持する。整理完了後にR1へ進む。S2は共通実行入口と環境設定例、設定の適用状態、配置・撤去手順を整備し、対象取り違えや不正な実行順を防ぐオフライン17テストで確認。実AWS操作・IAM更新・DNS変更は行っていない。

### 検証済みの範囲と限界

基準コードは採用UI・Go API・AWS定義を統合した版（main 15c2907）。以下は再検証を含む各層での到達点であり、今回の文書整理で試験を再実行した結果ではない。

| 対象 | 結論 | 条件・限界 |
|---|---|---|
| フロント・Go・監視 | ビルド・型検査、SSR 3件、runtime 3件、Go race付きテスト・vet、監視2件は成功 | SSRは固定API。GoのDB試験は接続設定なしではSKIPする |
| 採用UI | 固定APIによるオフライン画面試験11件で、狭幅・目次・編集状態・失敗表示等を確認 | 実API・DBを通した採用UIの管理操作やハイドレーションの通し確認は未完了 |
| DB・接続保護 | 実PostgreSQLの保存・公開版分離・競合、アプリロールのDDL拒否、TLSの誤CA・ホスト名不一致の拒否を確認 | ローカルの専用試験であり、本番復元や全脅威の評価ではない |
| AWS実経路 | 新UI・Go・RDSのHTTPS経由31項目を確認。本文・目次SSR、静的配信、認証・Origin・Cookie、保存・公開・更新・非公開・競合を確認 | 仮記事によるHTTP確認。実ブラウザでの管理操作・全機能負荷ではない |
| 独立更新 | NodeとGoを個別に再配置して、他方のタスクが変わらず、保存と応答が維持されることを確認 | 同じイメージへの置換。不良版からのロールバックや無停止保証ではない |
| 負荷・容量 | ローカル200記事×50KiB・閲覧負荷でNodeのCPU増量による待ち時間改善を確認。AWS空一覧の30要求も成功 | 同期・画像・バックアップを含む容量は未確定。小規模試験を本番保証にしない |

## 残る6つの作業単位

「実装済み」「検証済み」「公開済み」を区別する。完了は完了条件を検証した時点で更新し、ファイルを作っただけでは完了にしない。

| ID | 作業単位・現在の状態 | 完了条件 | 依存 |
|---|---|---|---|
| R1 | 外部記事連携：取得調査のみ | Qiita/note/Wantedlyのメタデータを保存し、自作記事と元公開日順に混在。重複防止、補正/非表示保持、失敗時保持、同期結果・取得不足を検証 | API/DB/同期の契約を具体化。Wantedlyの非公式方式・取得範囲を扱う |
| R2 | 画像：未実装 | 認可付きアップロード、Markdown挿入・プレビュー、永続化、公開/下書き/非公開に応じた閲覧制御を検証 | 画像モデル・保存/配信/認可の設計。R4へ接続 |
| R3 | 保存・運用：基本認証と監視設定の一部のみ | 公開用認証と回復、変更時バックアップ、別環境への記事/画像復元、失敗の把握と通知を確認 | 保存世代・損失許容・通知先の具体化。復元はR2とも整合 |
| R4 | UI接続・仕上げ：採用画面実装、HTTP接続確認済み | 実ブラウザで実API/DBを通し編集・公開。R1〜R3の接続、結果不明時の扱い、端末・キーボード等の受入を確認 | UI/API境界の合意。採用UIは同じコードツリーへ統合 |
| R5 | AWS本番準備：基本構成の試験済み | 本番設定、独自ドメイン/HTTPS、秘密値管理、再現できる配備/更新/撤去手順、通知接続、容量・不良版からの戻し方を確認 | R1〜R3の資源・負荷を反映。本番課金とDNS変更は具体案で確認 |
| R6 | 統合確認・正式公開：未着手 | 追加機能を含む公開候補版で、混在/画像/認証/非公開保護/復元/負荷の通し確認。実記事投入、読者閲覧、本人投稿、運用手順と継続費用を確認して公開 | R1〜R5 |

R1〜R3が主要な未実装機能群。工数見積もりはまだなく、完成率・残り日数は算出しない。6項目は作業範囲の数であり、6操作・6往復で終わるという意味ではない。

## コードの基準とAWSの置き場所

- 個人GitHubの非公開 `course-k/course-k-blog`。**共通の参照先はmain**。作業はmainからブランチを切り、検証後にPRで戻す。mainへの取り込みを、そのまま正式公開や配備とは扱わない。
- AWSのIAMアクセス設定は維持。仮のアプリ・DB等は撤去済み。独自ドメインのDNSは未変更。AWS検証のための最大72時間・目安10 USDの承認を、正式公開の継続課金へ拡張しない。

## 次に扱うものと既知の残件

1. 先にS1〜S4で既存の文書・基盤設定・実装・検証手順を整理する。その後、R1のAPI/DB/同期仕様・失敗時挙動・受入条件を具体化し、実装へ進む。全体のベンダー選定や採用UIの比較を最初から再開しない。
2. R1〜R3の契約をUIへ渡す。画像・同期・運用状態の専用ページを自動追加せず、合意済みの画面内へ接続する。
3. R5では、整理済みの[AWS手順と実行入口](../infra/README.md)を本番条件へ具体化し、実AWSで再検証する。S2のオフライン試験を配備の完全な再現性や本番準備完了と扱わない。

| 残件 | 管理先・対応 |
|---|---|
| Wantedlyは非公式HTML形式依存、取得範囲・条件が未確定 | R1。黙って手動登録へ切り替えたり、未取得を全件成功にしない |
| 一覧の次ページ有無は20件から推定、空の次ページがあり得る | R1/R4。混在一覧の契約と一緒に扱う |
| 結果不明のまま記事切替で警告が消えるコード経路 | R4。Editorのchooseはdirtyのみ確認してuncertainを解除する。コード上の指摘で、実ブラウザの再現・対応は未実施 |
| 新規作成の応答消失時に重複を防ぐAPI契約がない | R1/R4。現UIは自動再送を停止。既存記事はIDで再取得し、入力を保持する。冪等性の具体方式は未決 |
| 現認証は試作で、全体ログイン制限には第三者が枠を使い切れる弱点がある | R3。公開方式・制限強化・回復を検証 |
| 操作者の削除前スナップショット作成権限が不足 | R5。今回の撤去は管理者で完了。修正候補は未反映 |
| 元アクセステンプレートに未コミット変更がある | R5。今回の文書整理では変更しない。実配備前に採用版・反映版を照合 |

## 台帳の更新方法

状態・完了条件・依存・必要な判断と、重要な検証の結論・条件・限界を更新する。作業の時系列や失敗の応酬は残さない。仕様・選定理由は現行設計、UIの仕様・理由はUI設計へ反映する。LLM利用は設計書とPRに記載する。試験コードは実装と管理し、一時的な画像・ログ・取得データを文書の履歴として蓄積しない。
